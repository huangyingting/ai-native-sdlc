# ai-native-sdlc

Manually run **Copilot CLI call-chain demo** from **Actions → Copilot CLI call-chain demo → Run workflow**. Open the completed run's **Job Summary** to see the observed parent/subagent/model/tool hierarchy, timestamps, durations, parallel-agent peak, and token counts when emitted. Download the **copilot-trace-viewer** artifact from the same run and open its self-contained HTML file. The professional tabbed layout separates the run overview, agent-to-tool dependency graph, searchable span timeline, and request/response inspector. GitHub Actions Job Summaries do not run embedded JavaScript or iframes, so the viewer is linked as an artifact rather than embedded inline.

The dependency-free implementation in `trace-viewer/` is also a local composite action. The demo calls it with `uses: ./trace-viewer`; other workflows in this repository can pass an OTEL JSONL `trace-path`, an `html-path`, and optional model/evidence/message requirements.

The parent runs with `--model gpt-6-luna`; the repository's `aws-storage` and `azure-storage` custom agents also declare `model: gpt-6-luna`. Two independent subagents compare Amazon S3 with Azure Blob Storage: the AWS track calls read-only `web_fetch` on official AWS documentation, while the Azure track calls the public `microsoft-learn` MCP server's `microsoft_docs_search`. `--fleet` encourages parallel delegation but **does not guarantee any subagents or tool calls**. The summary flags missing tools, absent overlap, or a model mismatch, and the renderer fails the job if this evidence is missing. The repository owner's Copilot entitlement must include GPT-6 Luna.

The workflow runs only with `workflow_dispatch`, installs Node 22 and `@github/copilot`, and authenticates with the run's short-lived `GITHUB_TOKEN` (`contents: read`, `copilot-requests: write`). The repository owner needs a Copilot entitlement and available usage; usage in a personal repository is billed to that owner's Copilot seat. Organization repositories additionally need the Copilot CLI organization billing policy. No PAT or repository secret is required.

The checked-in `.github/mcp.json` allows only two read-only tools on the public, unauthenticated [Microsoft Learn MCP server](https://learn.microsoft.com/en-us/training/support/mcp); the headless workflow opts in to loading this workspace MCP configuration. AWS URL approval is restricted to `docs.aws.amazon.com`. In two smoke runs with an Actions `GITHUB_TOKEN`, the CLI did not make its built-in `web_search` available, even with the exact GitHub MCP tool preapproved, so this example uses `web_fetch` instead and labels it honestly.

CLI OpenTelemetry writes JSONL to the runner's temporary directory; **message content capture is off by default** and the raw trace is never uploaded. To show concrete request/response excerpts in expandable rows of the HTML viewer, check **include_messages** when manually dispatching. This captures full content temporarily on the runner; only bounded, escaped, token-redacted excerpts are published in the artifact. Redaction is best-effort, so **do not enable this option on private prompts, sensitive repositories, or sessions with secrets**. The renderer accepts both direct CLI span records and OTLP `resourceSpans[].scopeSpans[].spans[]`. A missing or malformed trace fails visibly (even if Copilot fails). Treat artifacts and the Job Summary as public in this repository.

Run the local, dependency-free parser tests with `node --test trace-viewer/render-trace.test.mjs`.
