# ai-native-sdlc

Manually run **Copilot CLI Agent Demos** from Actions. Open the completed run's **Job Summary** to see the observed parent/subagent/model/tool hierarchy, timestamps, durations, parallel-agent peak, token counts, and cost. Download the **copilot-trace-viewer** artifact from the same run and open `copilot-trace-report.html`. The **Copilot CLI Trace Viewer** is a compact correlated workspace with two primary tabs: **Trace** combines the waterfall, status/error filtering, and selected-span inspector; **Dependencies** shows the agent/model/tool call graph with the same inspector. Selecting any span highlights its parent, children, and agent branch. The dependency map can be downloaded as SVG or PNG. GitHub Actions Job Summaries do not run embedded JavaScript or iframes, so the viewer is linked as an artifact rather than embedded inline.

Repository collaborators can choose one of four **Copilot CLI demo** issue forms. GitHub Issue Forms cannot update textarea defaults when a dropdown changes, so each orchestration pattern has its own form with one visible, editable task. The selected pattern's orchestration contract is injected automatically rather than exposed as a second prompt field. Creating or reopening the resulting `agent-trace` issue starts the same workflow. Both model selectors and redacted message capture remain available. When the run finishes, the workflow posts the final result, trace diagnostics, dependency graph, workflow link, and interactive HTML artifact link back to the originating issue.

Issue comments always include a GitHub-rendered Mermaid dependency graph. To additionally embed the generated PNG as a GitHub user attachment, configure the optional `AGENT_TRACE_MEDIA_TOKEN` Actions secret with a user token that can access this repository. GitHub's short-lived Actions `GITHUB_TOKEN` is not accepted by the user-attachments upload endpoint and returns 404; the workflow therefore never uses it for media upload and safely falls back to Mermaid if the optional upload is unavailable.

The issue form and manual dispatch support four reusable orchestration patterns:

- **Direct execution** handles the task without delegation, providing a cost and latency baseline.
- **Parallel delegation** fans out independent subtasks or perspectives and synthesizes their results.
- **Critic-reviser loop** challenges an initial position before producing a revised conclusion.
- **Sequential pipeline** passes one subagent's result into the next stage before final synthesis.

The repository stores only these stable orchestration patterns. Each issue supplies an editable task, so every issue can become a new demo without adding implementation files or changing the workflow. Copilot CLI decides the concrete subagent type at runtime.

Every pattern includes a tested default task and an internal orchestration contract. Users can run the default with one click or replace the task while preserving the selected coordination pattern.

See [Copilot CLI agent orchestration patterns](docs/copilot-cli-agent-orchestration-patterns.md) for execution diagrams, model behavior, validation signals, failure interpretation, and guidance on choosing a pattern.

The dependency-free implementation in `trace-viewer/` is also a local composite action. `trace-model.mjs` normalizes direct CLI JSONL and OTLP envelopes into one trace view model; `html-renderer.mjs` renders that model; `render-trace.mjs` is the action/CLI adapter. The demo calls it with `uses: ./trace-viewer`; other workflows can pass an OTEL JSONL `trace-path`, a stable `html-path`, optional model/evidence/message requirements, and an optional replacement pricing catalog.

The workflow exposes **Orchestrator model** and **Subagent model** choices, both defaulting to `gpt-6-luna`. The orchestrator delegates work and synthesizes the final response; dynamically created subagents are instructed to use the selected subagent model. Parallel demos use `--fleet`; sequential demos let the orchestrator create each subagent only after the previous result returns. OTEL trace evidence validates branch counts, concurrency/order, tool use, and observed models without depending on predetermined agent names. The repository owner's Copilot entitlement must include the selected models.

The workflow runs from `workflow_dispatch` or an authorized `agent-trace` issue, installs Node 22 and `@github/copilot`, and authenticates Copilot with the run's short-lived `GITHUB_TOKEN` (`contents: read`, `copilot-requests: write`). The repository owner needs a Copilot entitlement and available usage; usage in a personal repository is billed to that owner's Copilot seat. Organization repositories additionally need the Copilot CLI organization billing policy. The optional user-attachment upload uses the separate `AGENT_TRACE_MEDIA_TOKEN` secret described above.

The checked-in `.github/mcp.json` allows only two read-only tools on the public, unauthenticated [Microsoft Learn MCP server](https://learn.microsoft.com/en-us/training/support/mcp); the headless workflow opts in to loading this workspace MCP configuration. AWS URL approval is restricted to `docs.aws.amazon.com`. In two smoke runs with an Actions `GITHUB_TOKEN`, the CLI did not make its built-in `web_search` available, even with the exact GitHub MCP tool preapproved, so this example uses `web_fetch` instead and labels it honestly.

CLI OpenTelemetry writes JSONL to the runner's temporary directory; **message content capture is off by default** and the raw trace is never uploaded. To show concrete request/response payloads, check **include_messages** when manually dispatching. Copilot CLI may replace a large tool result with a runner-temp file reference. Before the runner is destroyed, the trace model safely resolves only Copilot tool-output files under the runner temp directory, redacts their contents, and embeds the result in the report. Payloads are preserved up to a 1 MiB safety ceiling instead of being arbitrarily clipped at 1,200 characters. Absolute runner paths are not published. Redaction is best-effort, so **do not enable this option on private prompts, sensitive repositories, or sessions with secrets**.

Cost uses `gen_ai.usage.cost` when OTEL reports it. Otherwise the renderer normalizes each span's model name, looks it up in `trace-viewer/model-pricing.json`, selects its default or long-context tier, and estimates the call from observed input/output/cache token counts. The viewer shows the trace total, each model call, and root-inspector rollups by agent branch and model, including priced-call coverage and token totals. The bundled catalog covers the current OpenAI, Anthropic, Google, Microsoft, xAI, and Moonshot models listed on GitHub's [models and pricing](https://docs.github.com/en/copilot/reference/copilot-billing/models-and-pricing) page. A workflow can pass `pricing-path` to replace the bundled catalog. Unknown models or calls without token usage display `—` and are excluded from the total rather than receiving another model's rate.

The renderer accepts both direct CLI span records and OTLP `resourceSpans[].scopeSpans[].spans[]`. A missing or malformed trace fails visibly (even if Copilot fails). Treat artifacts and the Job Summary as public in this repository.

OpenTelemetry span status `UNSET` (`code: 0`) does not mean that the outcome is unknown. The renderer treats a span as successful unless OTEL reports `ERROR` (`code: 2`) or an error attribute, which prevents healthy auto-instrumented tool calls from being labeled `unknown`.

Failed spans show the OTEL failure reason in the inspector even when message capture is disabled. A fast failed tool call can be an intentional permission-policy rejection—for example, `web_fetch` is restricted to `docs.aws.amazon.com`, while Azure documentation must use the Microsoft Learn MCP tools.

Run the local, dependency-free parser tests with `node --test trace-viewer/render-trace.test.mjs`.
